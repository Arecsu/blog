# Architecture

## Stack

- **Astro 7**, static output (`dist/`). No adapter, no server runtime.
- **Svelte 5** islands for the only stateful UI: header/theme switch, the recipe
  ingredients list, and the recipe process/dock.
- **MDX** content collections. **Sätteri** is the Markdown processor (Astro 7's
  native processor). MDX inherits the configured plugins.
- **SCSS** with CSS custom-property tokens.
- **Vitest** for units/content; **Playwright** for browser behaviour.

`trailingSlash: "always"` is deliberate: every route is a directory with `index.html`,
and internal links end in `/`. The old Nuxt site canonicalised the same way.

## Routes

```
src/pages/
  index.astro                 /
  notes/index.astro           /notes/
  notes/[...slug].astro       /notes/<slug>/
  recetas/index.astro         /recetas/
  recetas/[...slug].astro     /recetas/<slug>/
```

`getStaticPaths` filters `draft: true` in production only; the index lists always
hide drafts. `notes/worth` and the draft recipes therefore exist in `astro dev` but
are not generated by `astro build`.

## Content collections

`src/content.config.ts` defines:

- `recetas` (`src/content/recetas/*.mdx`) — recipe frontmatter, process body.
- `notes` (`src/content/notes/*.mdx`) — note frontmatter and body.
- `recipeExtras` (`src/content/recipe-extras/*.mdx`) — an optional MDX partial per
  recipe: the ingredients intro (pizza/pan) or the legacy ingredient list
  (masa-madre/pakoras/pochoclos-salados). It is fetched by the recipe page, not a
  route.

The Zod schema is intentionally strict. Cross-field rules that Zod cannot express
(unique ingredient IDs, allocations summing to the total, positive quantities) are
enforced by `validateRecipeIngredients` during the build and in `tests/content.test.ts`.

## MDX pipeline

`astro.config.mjs` sets:

```ts
markdown: {
  processor: satteri({
    features: { smartPunctuation: false },
    mdastPlugins: [emojiSyntax],
    hastPlugins: [externalLinks],
  }),
}
integrations: [mdx(), svelte()]
```

- `smartPunctuation: false` is required. Sätteri defaults SmartyPants on in Astro,
  which turns `...` into `…` and `""piedra""` into curly quotes; the Nuxt site
  rendered the source punctuation verbatim. Keep the authored text intact.
- `emojiSyntax` removes the authoring delimiters `:🍕:` / `;🍕;`, leaving the glyph.
- `externalLinks` adds `target="_blank"` and `rel="nofollow noopener"` to external
  links.
- Do not add `remarkPlugins`/`rehypePlugins` or `@astrojs/markdown-remark`. Astro 7
  defaults to Sätteri and the unified processor is legacy.

## Recipe page flow

`src/pages/recetas/[...slug].astro`:

1. `getStaticPaths` filters drafts.
2. `validateRecipeIngredients(entry.data.ingredientGroups)` throws on bad data.
3. `sanitizeRecipeGroups` removes emoji authoring delimiters once on the server.
4. `render(entry)` produces the process body. The page wraps it in
   `RecipeProcess.svelte`.
5. `getCollection("recipeExtras")` finds the matching intro/legacy partial and
   renders it inside `RecipeIngredients.svelte` as a slot.
6. `Astro.locals.recipe = { groups }` before the MDX body renders, so
   `<RecipeAmount>` can resolve its ingredient without threading props through MDX.
7. The title width is computed from `recipeTitleWidth` + the Noto Serif metrics JSON,
   and passed as `--recipe-title-width`.

The MDX body contains only process prose and `<RecipeAmount>` elements. The
`RecipeIngredients`/`RecipeProcess` wrappers from Nuxt Content are gone: the page
owns those sections, which is why the islands can receive the recipe data directly.

## Islands and state

- `Header.svelte` (`client:idle`) owns the menu/title swap and the theme switch. Its
  scroll state is local to the route and resets when the header remounts; do not
  persist the header.
- `RecipeIngredients.svelte` (`client:load`) owns the structured/legacy ingredient
  list, scale menu, drawer, sticky measurement, and column measurement.
- `RecipeProcess.svelte` (`client:load`) owns the process prose enhancement, inline
  amount popover, section tracking, and mobile dock.
- `src/lib/recipe-viewer-store.ts` is the cross-island nanostore: `scale`,
  `showAmounts`, `drawerOpen`, `drawerScope`, `currentSection`, plus the recipe data.
  `initRecipeViewer(recipe, token)` resets the scale when the page instance changes.
  The build-time token is stable, so a client-side `navigationToken` is created on
  `astro:before-swap`; both islands on the new page share it. This is what makes
  returning to a recipe reset the scale to 1. `showAmounts` persists in
  `localStorage` under `recipe-show-amounts`.
- The header title is passed down as a prop from the recipe page; other pages pass
  an empty title so the menu always shows.

## Styling

Global styles are imported once in `Base.astro`:

```
inter.css → reset.scss → _tokens.scss → base.scss → _tooltip.scss → emoji font CSS
```

Tokens are CSS custom properties in `_tokens.scss`; Sass variables are only
breakpoints/mixins in `_vars.scss`/`_mixins.scss`. Component styles are scoped.
Recipe prose is MDX slot content and is styled globally in the recipe page with
`:where()` element defaults; do not try to scope those selectors.

## Head preferences

Two tiny inline scripts run before first paint, like a theme bootstrapper:

- `head-theme-switch.js` sets `html[theme]` and the `theme-color` meta from
  `localStorage`/`prefers-color-scheme`.
- `head-recipe-amounts.js` sets `html[data-recipe-amounts="hidden"]` when the reader
  hid inline quantities, so the chips never flash in and reflow the process prose.
  CSS hides from that attribute; the recipe store keeps it in sync after hydration.

Keep these inline and in the head. They are display preferences that must be correct
before the first paint; moving them into an island reintroduces a layout shift.
ClientRouter does not re-run head scripts on navigation, so `Base.astro` also copies
the live `theme` / `data-recipe-amounts` attributes onto `event.newDocument` in
`astro:before-swap`, and the `theme-color` meta uses `transition:persist`. A hard
load still goes through the inline scripts.

## Fonts and emoji

- **InterVariable** (`src/assets/font-inter/InterVariable.woff2` + italic) is the
  body/UI sans. It is the current Inter 4.1 variable family, with optical sizing and
  the features the site uses. Preloaded with `crossorigin`.
- **Noto Serif** (`@fontsource/noto-serif` latin 400) is the recipe title/heading
  serif. Preloaded from the package's woff2 via `?url`.
- **Fluent Emoji Colour** (`src/assets/fluent-emoji-color`) is split into COLRv1 and
  OpenType-SVG chunks with `unicode-range`. The font stack appends
  `"Fluent Emoji Color"` after Inter, Noto Serif, and the mono stack, so any emoji
  glyph falls through to it. Only the chunks for emoji on the page are fetched.
- Title/controls icons are **inline SVGs** from unplugin-icons, not the emoji font:
  they must paint immediately with no font-loading flash. The static map is
  `src/components/icons.ts`; `Icon.svelte` is the sizing/colour wrapper.

## ClientRouter, scroll ownership, and view transitions

`Base.astro` mounts `<ClientRouter />`. The **document does not scroll**: `.page-scroll`
is a `100dvh` scroll container and carries `view-transition-name: route-viewport`.
Its snapshot is always exactly the visible viewport, so `transform-origin: center` is
the reader's centre at any scroll offset — the reason the wrapper exists. `main` is
not a named transition piece.

The route enter is `route-enter`: opacity, a small blur, and `scale(0.99)` → `1`, timed
by `--transition-enter-duration` / `-delay` / `-ease` / `-blur` / `-scale` in
`_tokens.scss`. The exit is instant (`::view-transition-old` is `display: none`) and
every named group has `animation: none`, otherwise the UA morphs the old box into the
new one and an off-screen piece flies in from above. `site-header` is a separate piece:
it is identical in place on every route, so it swaps instantly and never scales with
the page. Reduced motion disables the enter animation.

While the snapshot scales, the scrollbar keeps its gutter but not its paint
(`html[data-astro-transition] .page-scroll` + the pending marker). `page-scroll.ts`
removes the marker on the next real scroll.

### Inner-scroll restoration

`src/scripts/page-scroll.ts` owns scroll restoration for `.page-scroll`; Astro's own
window-scroll bookkeeping is harmless because window scroll is always zero. It keys
positions by `Navigation.currentEntry.key` (stable across reloads), remembers before
swapping, restores in `astro:after-swap` (before the incoming snapshot), handles
fragment-only navigations through `currententrychange`, and checkpoints to
`sessionStorage` on `scrollend`/`pagehide`. Previous/next entries restore their exact
position; fresh navigations start at the top or resolve their fragment.

Two supporting details are load-bearing:

- `<html>` display preferences (`theme`, `data-recipe-amounts`) are set on
  `event.newDocument` in `astro:before-swap`. ClientRouter replaces every root attribute
  with the incoming document's, whose markup was parsed without the inline head
  scripts; without the copy a dark page painted one light frame.
- `<meta name="theme-color">` is `transition:persist`, so ClientRouter keeps the live
  meta node instead of the incoming page's light default.
- `vite.build.cssCodeSplit: false` keeps every route's CSS in an eagerly loaded bundle.
  With per-route chunks Safari applies the incoming stylesheet after the swap: the
  unstyled page is short, the restored scroll clamps, and the layout then jumps. Keep
  the CSS imports reachable from the initial page; do not reintroduce route CSS chunks.

The header is **not** `transition:persist`: its active link and title are route data.
A fresh header from the new HTML is cheaper and correct; the named, unanimated piece
keeps it visually stable.

## Caching

`public/_headers` + `public/netlify.toml`:

- HTML: `public, max-age=600, must-revalidate` (deploys are picked up quickly).
- `/_astro/*` (JS, CSS, fonts, emoji chunks): one year, immutable.
- favicons/images: one week, immutable.

`Base.astro` also contains the inline retry for a module script that a CDN served as
HTML from a not-yet-propagated asset URL. It is intentionally the first script in the
head. See [`deployment.md`](deployment.md).

## Performance notes

The recipe page ships three Svelte islands and no Vue/Nuxt runtime. The ingredient
drawer uses a native `<dialog>`, moves the existing panel (never a copy), inserts one
placeholder, and uses overlay gradient fades instead of `mask-image`. The amount
popover is shared by every inline amount. See [`performance.md`](performance.md) for
the measured comparison with the Nuxt implementation.
